# Спортивный клуб — SQLite

База содержит 26 тестовых строк. `members` хранит участников, `trainers` — тренеров, `classes` — отдельные занятия в расписании, `visits` — записи и фактические посещения, `payments` — оплаты и сроки действия абонементов. На схеме `1 : N` означает связь «один ко многим».

У всех таблиц есть первичный ключ. Внешние ключи связывают таблицы; важные поля обязательны, e-mail и пара участник–занятие уникальны. CHECK проверяет дату рождения, положительное число мест и сумму оплаты, порядок дат занятия и абонемента, статус записи. Индексы добавлены для связей. SQLite проверяет внешние ключи только при включённом `PRAGMA foreign_keys = ON` для каждого соединения. Ограничение количества записей вместимостью группы здесь не реализовано.

`checks.sql` содержит восемь запросов: активные абонементы на текущую дату; записи по датам; занятия тренеров; участники без посещений за 30 дней; три популярных занятия; выручка по типам; пересечения занятий участника; свободные места. Активность и давность рассчитываются на дату запуска, поэтому результаты со временем меняются. Конфликт Анны специально оставлен в тестовых данных для проверки запроса.

## Запуск в DBeaver

1. Создайте подключение SQLite к новой пустой базе и откройте SQL-редактор.
2. Выполните целиком `schema.sql` в этом соединении: он включает проверку внешних ключей.
3. Выполните целиком `seed.sql` один раз.
4. Откройте `checks.sql` и выполняйте запросы по очереди, просматривая результаты. Для готового примера можно вместо шагов 1–3 открыть `sports.db`.

`erd.png` показывает связи. Данные и расписание учебные; даты оплаты и начала действия хранятся в формате YYYY-MM-DD, время занятий — YYYY-MM-DD HH:MM. Суммы указаны в рублях.
